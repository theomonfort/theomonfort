### 実際に何が変わる？

**悪意のある依存関係は、PR がレビューされる前でも、インストール中にコードを実行できます。** Package firewall はダウンロード経路上でポリシーを適用します。エージェントがコマンドごとの人間の承認なしにパッケージをインストールする場合も対象です。

設定済みの環境は、公開レジストリに直接アクセスする代わりに、**メタデータ要求とパッケージのダウンロードを GitHub の firewall 経由にします**。Enterprise のポリシーを評価し、条件を満たさない要求をブロックします。依存関係のアラートや PR チェックを補完するもので、置き換えるものではありません。

### 何をブロックできる？

- **公開直後のバージョン**：公開後の最低経過日数を設定し、脅威が発見されるまでの待機期間を設けます。例えば、公開から 3 日以上経過したバージョンだけを許可できます。
- **既知のマルウェアと脆弱性**：GitHub Advisory Database と照合します。脆弱性は、インストールをブロックする重要度のしきい値を管理者が選択できます。
- **アテステーションの後退**：以前のバージョンにあった SLSA アテステーションが新しいバージョンで欠落している場合にブロックします。公開プロセスの侵害を示す可能性があります。
- **新たなインストールスクリプト**：設定ドキュメントには、`preinstall` や `postinstall` など、新しく追加されたインストールスクリプトをブロックする制御も記載されています。

例えば、数分前に公開されたバージョンを CI がダウンロードしようとした場合、**マルウェアのアドバイザリがまだなくても**待機期間のポリシーで止められます。リスクを減らす仕組みであり、古いパッケージや許可されたパッケージの安全性を保証するものではありません。

### 接続先の設定と例外運用が重要

**Enterprise → Policies → Package firewall** で制御を設定し、パッケージマネージャーの接続先を Enterprise 固有の firewall レジストリに変更します。認証には Enterprise メンバーのトークンを使い、シークレットストアで管理します。設定ファイルに実値をコミットしないでください。

**ポリシーを有効化するだけでは、通信経路は変わりません。** チェックされるのは firewall を通る要求だけです。開発端末、エージェント環境、CI ランナー側の設定も必要で、公開レジストリへの直接接続が残っていると迂回できます。

ブロックされた要求には例外申請用リンクが表示されます。緊急のセキュリティ修正版が待機期間に引っかかった場合などに利用でき、Enterprise 管理者とセキュリティマネージャーが審査します。

### 利用条件

**2026-10-22 時点**では **npm パッケージのみ**に対応するパブリックプレビューで、**GitHub Enterprise Cloud**（データ所在地を含む）が対象です。**プレビュー中は無料**で、GitHub は一般提供時に従量課金を予定しています。
