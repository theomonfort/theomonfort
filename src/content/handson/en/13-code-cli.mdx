### 13.0 — (If you're not on a Codespace) Install Copilot CLI

The workshop Codespace already has Copilot CLI **pre-installed**, so you can skip this step. Only if you're working locally and don't have it yet, install it with one of the following:

```bash
# npm (all platforms / requires Node.js 22+)
npm install -g @github/copilot

# Homebrew (macOS / Linux)
brew install copilot-cli

# Install script (macOS / Linux)
curl -fsSL https://gh.io/copilot-install | bash
```

<Aside type="positive">

**💡 TIP**: For more information, please refer to the [official installation documentation](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli).

</Aside>

### Key commands

| Command       | Description                                            |
| ------------- | ------------------------------------------------------ |
| `/help`       | List available interactive commands                    |
| `/model`      | Pick the AI model (Claude / GPT, etc.)                 |
| `Shift+Tab`   | Switch mode (plan / agent)                             |
| `/ide`        | Connect to an IDE workspace                            |
| `/allow-all`  | Allow tool execution without confirmation (Autopilot)  |
| `/fleet`      | Run multiple agents in parallel                        |
| `/tasks`      | Check the status of running fleet tasks                |
| `/context`    | Show context window token usage                        |
| `/compact`    | Summarize conversation history to free context         |
| `/chronicle`  | Analyze session history and usage                      |
| `/resume`     | Resume the previous session                            |

### 13.1 — Launch Copilot CLI

First, review and merge the earlier exercise PRs (or your checkpoint PR) yourself. You can try the site on the prepared checkpoint branch before merging; when ready for `/fleet`, update local `main`:

```bash
git checkout main
git pull
```

Then launch Copilot CLI from the VS Code terminal:

```bash
copilot
```

### 13.2 — Pick a model and enable Autopilot

Inside the CLI, run:

```
/allow-all
```

```
/model
```

Pick the most capable model available (e.g., Claude Opus 4.6).

### 13.3 — Implement Issues in parallel with `/fleet`

Select unfinished work whose prerequisites are merged. With checkpoint3, reuse its verified 3D and work on `galaxy-audio`; without it, build 3D first. If only one task is ready, use a single CLI session. For multiple independent tasks, use `/fleet` with the prompt below. It also asks for a rubber-duck review.

```
/fleet Read the Part 6 Issues identified by [playbook:key] and their acceptance criteria.
Select only unfinished tasks whose prerequisites are merged.
Keep presentation-tests for Part 11 and daily-repo-status for Part 14.
Inspect whether checkpoint3 already satisfies playbook-3d; reuse it instead of rebuilding.
If 3D is missing, implement and merge it before galaxy-audio. If checkpoint3 supplies it,
merge the checkpoint PR before starting audio. Do not run dependent tasks concurrently.
If only one task is ready, work on that one without spawning extra agents.
Parallelize only independently scoped ready tasks, not every open Issue or label.

Each agent should follow this flow:
1. Create a branch matching the Issue number (`fix/<number>-<slug>`)
2. Implement the fix
3. Verify it runs with `npm run dev`
4. Commit and open a PR (include `Closes #<number>` with the actual Issue number in the body)

Once all PRs are open, run a rubber-duck review on each implementation.
```

⏱ ~10–15 minutes

When independent tasks are available, the CLI can run them on separate branches through implementation and PR creation. Review and merge prerequisite PRs before starting dependent tasks. Check completed acceptance criteria instead of recreating features already present in your snapshot.

To check progress during and after execution:

```
/tasks
```

This lists the status of each fleet agent (running / done / failed) along with the current step.

<Aside type="positive">

**Key point**: Having a different model (Codex) review what another model (Claude) implemented helps you avoid same-model bias and surface blind spots. Copilot CLI ships with a built-in **rubber-duck subagent** that reviews the work critically using a different model (e.g. GPT) from the main session agent (e.g. Claude) — adding "after implementation, do a rubber-duck review with a different model" to your prompt invokes it automatically. See [About the rubber duck agent](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/rubber-duck) and [About custom agents](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents) for details.

</Aside>
