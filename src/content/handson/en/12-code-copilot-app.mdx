### 12.1 — Bring the repositories and brief together

First, **save, commit and push your Codespaces work**, then review and merge your Test & Secure PRs. Note the resulting `main` commit. Open the Copilot App with access to your hands-on repository and continue from that updated, reviewed state, not a stale local `main`. Importing checkpoint3 is not a prerequisite.

1. Use **+ beside Projects** to create a Project for this website.
2. Add these three repositories to the Project. Only your hands-on repository is an implementation target.
3. [Download the Word brief](/theomonfort/handson/copilot-app-project-brief.docx), then use **Library → Add → Add file…** to attach it.

The solar-system reference deliberately differs from our site: Sun + eight astronomy planets, navy/amber styling and a detail panel. Adapt its data and interactions to **SDLC categories, Playbook routes and the retro theme**, rather than copying the astronomy UI.

### 12.2 — Compare first, then approve a plan

Send this to the Project, replacing the repository and reviewed commit:

```text
Read the Word brief in Library and compare all three repositories.
Only <my hands-on repo> may change; the two irl-odyssey repos are read-only references.
Use reviewed main at <commit> as the base. Inspect its current features and tests first.
Propose an adaptation plan: map the solar-system design to our SDLC categories,
routes and theme, and integrate read-only Zettelkasten with curated bundled notes.
Inspect and reuse any existing 3D and Zettelkasten from my own work or checkpoint3;
adapt only missing requirements instead of rebuilding either. Preserve source licenses.
Show what already works, what needs adapting, and proposed tests. Wait for my approval.
```

Plan both integrations as Project tasks from the Word brief, not from the initial Part 6 Issue catalogue. Checkpoint3 already includes both; if they are present in your repository, compare them with the brief and adapt only missing requirements.

### 12.3 — Implement only the agreed adaptations

**3D first.** After reviewing the plan, send:

```text
Implement the approved 3D adaptation only in <my hands-on repo>,
on an integration branch from the agreed base. Keep both reference repos unchanged.
Preserve the 2D catalogue, presentation and existing localized content.
Keep TOC labels in English without translating the article content. Reuse 3D already present.
Ask which tests to add, implement the agreed tests and show the diff. Stop before graph integration.
```

Review the 3D result in **Overview** and the conversation: destinations must match your site's categories/routes and the existing site must still work.

**Then inspect and adapt the read-only graph**, on the reviewed branch that retains your exercise work and 3D:

```text
Inspect and reuse any existing Zettelkasten in <my hands-on repo>, including work based on checkpoint3.
Implement only approved gaps, or integrate it if absent, continuing from our reviewed 3D work.
Keep both reference repos and existing features unchanged.
Reuse mountZettelkasten with readOnly: true and apiBaseUrl: null; set apiBaseUrl: null on every vault.
Keep graph exploration, search, note reading and links using curated bundled data.
Expose no visitor edit/create/rename/delete/import actions, editor shortcuts or write endpoints.
Do not delete the source editor; adapt its existing read-only configuration.
Ask which proposed tests to add, implement the agreed tests, and show the diff.
```

Check that graph exploration, search, reading and links work without editing or a write API. Review the target-only diff and license notices before opening and merging the integration PR.
