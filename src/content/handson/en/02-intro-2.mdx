In this section you'll copy the following template repository to create your hands-on repository, then open it in a **Codespace** to start working. If you can't use Codespaces, clone it locally and work there instead.

**Project URL**: [https://github.com/theomonfort/Github-copilot-workshop](https://github.com/theomonfort/Github-copilot-workshop)

### 2.1 — Create your hands-on repository

1. Open the project URL in your browser
2. Click the **Use this template** button in the top right and select **Create a new repository**

![Use this template → Create a new repository](/theomonfort/handson/img/use-this-template-dropdown.png)

3. On the repository creation screen, configure the following:
   - **Owner**: select an **Organization** where you can freely create test repositories (Copilot / Actions / GHAS / Codespaces enabled)
   - **Repository name**: any name you like (e.g., `hands-on-yourname`)
   - **Visibility**: select **Private**
   - Leave **Include all branches** unchecked; a copy of `main` is enough, including for the checkpoints below.

4. Click **Create repository**

![Click the Create repository button](/theomonfort/handson/img/create-repository-form.png)

### 2.2 — Open the repository

Open your newly created repository in a dev environment. **Option 1 (Codespaces)** is recommended, but if you can't use it, **Option 2 (Local)** works too.

#### Option 1: Codespaces (recommended)

1. On your newly created repository's page, click the green **Code** button
2. Select the **Codespaces** tab
3. Click **Create codespace on main**

<Aside type="negative">

Starting a Codespace can take a few minutes. Please wait for the DevContainer build to finish.

</Aside>

#### Option 2: Local

1. Open a **terminal** in VS Code (menu **Terminal → New Terminal**, or `` Ctrl+` ``)
2. On the repository page, open the green **Code** button → **Local** tab → **GitHub CLI** tab, and copy the clone command

   ![Copy the clone command from Code → Local → GitHub CLI](/theomonfort/handson/img/clone-github-cli.png)

3. Paste it into the terminal to clone the repo locally:

   ```bash
   gh repo clone <owner>/<repo-name>
   ```

4. Open the cloned folder in VS Code:

   ```bash
   code -r <repo-name>
   ```

<Aside type="negative">

Working locally means you'll need to provide the tools bundled in the DevContainer yourself — Node.js 22, GitHub CLI (`gh`), Copilot CLI (`@github/copilot`), gh-aw, and so on.

</Aside>

Either way, the DevContainer sets up a Node.js 22 environment with the following pre-installed (locally, use a DevContainer-aware setup or install them manually):

- GitHub Copilot & Copilot Chat extensions
- GitHub CLI (`gh`)
- GitHub MCP Server (workspace-root `.mcp.json`; verify it in the next step, then add Context7)
- Copilot CLI (`@github/copilot`)
- gh-aw (Agentic Workflow CLI)

### 2.3 — Review the source content

`src/content/playbook/` contains several Markdown files about GitHub and Copilot — the material for today's site. Each file's frontmatter defines `title` / `summary` / `icon` / `color` and an SDLC `category` (introduction / plan / develop / review / secure / operate, etc.). Assets you can use to build the site — icons and images (such as planet artwork) — are also provided under `public/`.

<span id="checkpoints"></span>

<Aside type="reference">

**Jump to a checkpoint:** In the terminal at the root of **your generated repository**, run `./checkpoint1` (PLAN + base site, before Review/Cloud Agent), `./checkpoint2` (+ presentation, before Test & Secure), or `./checkpoint3` (+ tests/CI, before CLI/Operate). Each works independently. Save editor buffers first. The script imports the snapshot files into a new branch and PR from your remote `main`, without merging; keep any printed stash reference. Review the replacement/deletion diff. Issues and repository settings are not copied.

**Run the site:** On the prepared branch, run `npm ci && npm run dev`, then open `/playbook` through the Codespaces forwarded port or the printed local URL. You can try it before merging the PR. The scripts do not install dependencies or start servers; later restarts need only `npm run dev` unless dependencies changed. Older template copies may lack these scripts; see the [checkpoint README](https://github.com/theomonfort/Github-copilot-workshop#チェックポイントから-pr-を作る--create-a-checkpoint-pr).

</Aside>
