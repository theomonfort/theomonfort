### 8.1 — Set up the Context7 MCP server for the Cloud Agent

The MCP you set up in Part 3 was **for VS Code**. For the Cloud Agent to use MCP, you need a separate repository-level setting (shared by the Cloud Agent and Copilot Code Review).

1. On github.com, open your repository and click the **Settings** tab.
2. In the sidebar, go to **Code & automation** → **Copilot** → **MCP servers**.
3. Paste the following JSON into the **MCP configuration** field and click **Save MCP configuration**.

```json
{
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp",
      "tools": ["resolve-library-id", "get-library-docs"]
    }
  }
}
```

⏱ ~2 min

<span id="112--assign-an-existing-issue-to-the-cloud-agent"></span>

### 8.2 — Assign an existing Issue to the Cloud Agent

**Required first: `[playbook:presentation-core]` from [Step 6.6](/theomonfort/en/handson/code-copilot-chat/#66--file-the-improvements-as-issues).** Reuse the Issue prepared by `./checkpoint1` or create only the missing catalogue entries. Find it by its key, not an assumed Issue number. Keep `/playbook` as the landing page and add a presentation link from each card to `/playbook/<slug>/?present=1`, with arrow-key navigation and a section TOC. Review, try, and merge this PR before Test & Secure: [Step 11](/theomonfort/en/handson/test-secure-actions/) tests these controls.

1. On github.com, open your repository.
2. Click the **Issues** tab at the top.
3. From the list, open the presentation-mode Issue.
4. In the right sidebar, click **Assignees**.
5. Pick one of **Copilot** (GitHub), **Claude** (Anthropic), or **Codex** (OpenAI) from the list and assign it.

![Cloud Agent assignment screen](/theomonfort/handson/img/cloud-agent-assignees.png)

When you assign, you can customize:

- **Additional prompt** — extra instructions added on top of the Issue description.
- **Model selection** — pick from Copilot / Claude / Codex.
- **Base branch** — the branch the work starts from.

<Aside type="positive">

**Key point**: The Cloud Agent implements code and opens a PR (⏱ ~15 min per Issue). The validation-tool instructions in Step 4.1 do not enable repository checks. Code Review was configured in Step 7; this workshop adds CodeQL in Step 10 and the Playwright/Actions workflow in Step 11. Do not expect those later checks on this first presentation PR: run it and review the diff yourself.

</Aside>

<Aside type="reference">

**Recommended approach**:

- **Merge `presentation-core` first**, then work on `presentation-content`, `mermaid-rendering` and `responsive-navigation`. Parallelize only independent changes; these tasks may touch the same renderer.
- **Check the checkpoint2 milestone**: slide content, diagrams and navigation should work before testing.
- **Keep `playbook-3d` and `galaxy-audio` for Part 13**, and `daily-repo-status` for Part 14. The audio task depends on the merged 3D view.

</Aside>

<span id="113--review-the-pr"></span>

### 8.3 — Review the PR

The PR the Cloud Agent creates is opened as a **Draft**.

1. Open the PR and review the changes.
2. Click **Ready for review** to lift the draft state.
3. Copilot Code Review kicks off automatically.

<Aside type="negative">

**If you hit a conflict**: when multiple Cloud Agents are working in parallel, they can touch the same files and cause merge conflicts. Click **Resolve conflicts** → **Fix with Copilot** and Copilot will resolve the conflict for you automatically.

</Aside>

![Resolving conflicts with Fix with Copilot](/theomonfort/handson/img/fix-conflicts-copilot.png)

<span id="114--try-it-in-your-codespace-before-merging"></span>

### 8.4 — Try it in your Codespace before merging

Before you merge, it's smarter to actually run the Cloud Agent's PR in your Codespace and check it. Check out the PR branch with the `gh` CLI (replace `<PR-number>` with the real PR number).

```bash
gh pr checkout <PR-number> && npm ci && npm run dev
```

Open `/playbook` through the Codespaces forwarded port (or the printed local URL), then use a card's presentation link. Check `←` / `→`, switching sections in the TOC, and `Esc` back to the landing page. If something is wrong, comment on the PR for a fix. **Merge the working presentation PR before continuing to Test & Secure.**
