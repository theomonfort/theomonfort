Let's create two kinds of instruction file:

- **`.github/copilot-instructions.md`** — applied everywhere in the repo (language, stack, conventions)
- **`.github/instructions/frontend.instructions.md`** — a **path instruction** that only applies to frontend files (design tokens)

### 4.1 — Create the repo-wide instruction file

Create a new file at `.github/copilot-instructions.md` at the root of the repository, and paste the following content as-is (create the `.github` folder first if it doesn't exist):

```
# Copilot Instructions

## Language

- Write all responses, comments, commit messages, and PR descriptions in **English**.

## Stack

- **Astro** only. Do not use Next.js, React Router, or SvelteKit.
- Use Astro components (.astro) for pages and layouts.
- Use Astro **content collections** (src/content/) for markdown content.
- Style with Tailwind CSS. Add scoped <style> blocks when needed.
- Use TypeScript everywhere (.ts files and .astro frontmatter).

## Conventions

- Pages live in src/pages/.
- Reusable UI lives in src/components/.
- Markdown lives in src/content/<collection>/*.md. Schemas are defined in src/content.config.ts.
- The package manager is **npm**.

## Code review

- Run a **self-review** before submitting changes; align with existing files' conventions, naming, and templates.
- PR descriptions must always cover **what / why / how to verify** (the three points).
- For breaking changes (frontmatter schema, routing, build config), explicitly document the reasoning and impact.
- Split large changes into smaller PRs to reduce review load.

## Documentation lookups (must follow)

Before writing any **Astro** code, you **must call the following Context7 MCP tools first**:

1. Resolve the library ID with `resolve-library-id`.
2. Fetch the latest docs with `get-library-docs`.
3. Implement based on the docs you just fetched.

```

⏱ ~2 min

<Aside type="positive">

**Key point**: As soon as you **save** the file (no commit needed), VS Code loads it into every new Copilot Chat request. From here on, Copilot's responses switch to English and the stack constraints are enforced automatically. See [VS Code: Use custom instructions](https://code.visualstudio.com/docs/agent-customization/custom-instructions) for details.

</Aside>

### 4.2 — Create a frontend-only path instruction

Now create a **path instruction** that only applies to specific file patterns. VS Code only hands this rule to Copilot when you touch files that match the `applyTo` glob.

Create a new file at `.github/instructions/frontend.instructions.md`, and paste the following content as-is (create the `.github/instructions/` folder first if it doesn't exist):

```
---
applyTo: "**/*.{astro,css,tsx,html}"
description: "Frontend design tokens (Phosphor Cosmos HUD theme)"
---

# Frontend Design Rules

When working on styles, components, or layouts, always apply the tokens below.

## Theme

Phosphor Cosmos HUD — abyssal cosmos surfaces with a 28px blueprint coordinate cross-grid, cohesive phosphor telemetry accents, crisp sans-serif prose, and monospace HUD badges.

## Colors

| Role                       | Hex       | Tailwind              |
| -------------------------- | --------- | --------------------- |
| Deep inset / code          | `#04080e` | `bg-shadow-ink`       |
| Base cosmos                | `#060b12` | `bg-midnight`         |
| Elevated HUD panel         | `#0b1420` | `bg-deep-purple`      |
| Phosphor cyan              | `#5eead4` | `text-neon-cyan`      |
| Phosphor green             | `#86efac` | `text-gb-green`       |
| Starlight periwinkle       | `#93a8ff` | `text-neon-magenta`   |
| Solar champagne            | `#fcd34d` | `text-crt-amber`      |
| Coral alert (danger only)  | `#fb7185` | `text-coral-alert`    |
| Strong / heading text      | `#ecf7fb` | `text-phosphor`       |
| Body text                  | `#bad0de` | `text-phosphor-body`  |
| Muted metadata             | `#728fa3` | `text-phosphor-muted` |

Build the `body` background on `#060b12` with a subtle 28px blueprint coordinate cross-grid.

## Fonts

| Usage                                      | Font                                 | Tailwind       |
| ------------------------------------------ | ------------------------------------ | -------------- |
| Hero & section headings (H1, stat numbers) | `'Orbitron', 'IBM Plex Sans JP'`     | `font-display` |
| Body copy, card titles & prose             | `'IBM Plex Sans JP', 'Noto Sans JP'` | `font-body`    |
| HUD badges, tags, controls & code blocks   | `'IBM Plex Mono'`                    | `font-mono`    |

Use `font-display` for hero and section headers, `font-mono` for telemetry badges, tags, and code, and **`font-body` (IBM Plex Sans JP) for all readable card titles and prose**.

## Effects

- Elevated HUD panels: `rgba(11, 20, 32, 0.86)` with `border-radius: 3px` and a `2px` luminous top status rail.
- Borders: `1px solid rgba(94, 234, 212, 0.16)` (strong `rgba(94, 234, 212, 0.32)`).
- Solid bright accent buttons/badges must use dark `#04080e` (`text-shadow-ink` + `font-semibold`) foreground text.

## Do not

- Use bright / white backgrounds.
- Use oversized border radii (keep cards, pills, and controls crisp at `3px`).
- Overuse pixel fonts on body copy or long UI labels.
```

⏱ ~2 min

<Aside type="positive">

**Key point**: These design tokens are only handed to Copilot when you edit a `.astro` or `.css` file. They won't bleed into unrelated tasks like docs editing — less noise, more focus.

</Aside>
