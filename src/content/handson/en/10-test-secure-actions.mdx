<Aside type="reference">
[Official Playwright test agents](https://playwright.dev/docs/test-agents) provide a planner and generator using a test MCP server. No custom skill is needed. See also [GitHub Actions](/theomonfort/en/playbook/github-actions/?present=1).

Create `test-creation` from that working branch and use the existing `[playbook:presentation-tests]` Issue from Part 6. Reuse any existing tests rather than duplicating them.

### 9.1 — Create tests for Presentation mode

#### Prepare the official agents safely

The [updated Dev Container](https://github.com/theomonfort/Github-copilot-workshop/blob/2ee5b723164850e201d770a0522324bb643ff4b3/.devcontainer/devcontainer.json) prepares **Node.js 22, Playwright 1.58.2 CLI and matching Chromium** automatically. Older copies need the updated container configuration and a rebuild. The project's local `@playwright/test` dependency, configuration and agents are separate.

In Copilot Chat, send this setup prompt only for anything missing:

```text
Prepare this project's missing Playwright 1.58.2 dependencies, Chromium and config.
Generate official agents with init-agents --loop=vscode in isolation; merge planner/generator into .github/agents.
Connect their tools to one headless playwright-test MCP in root .mcp.json.
Preserve existing servers, workflows, instructions and tests; use an available model.
Set testDir to tests/e2e; keep generated tests and a working /playbook/ seed there.
Use Node 22 for setup, tests AND the MCP process. Verify tools work, then clean up.
```

Use the Copilot harness from [Part 3](/theomonfort/en/handson/plan-mcp/) and VS Code 1.105+. Check **Customizations → Agents** and start **MCP Servers → Workspace → playwright-test**, reviewing trust prompts. Outside the container, if the host uses another Node version, have Copilot launch Playwright setup, tests and MCP through `npx --package=node@22.23.4 node ./node_modules/@playwright/test/cli.js` and restart MCP. Changing only the terminal's Node does not change MCP; do not use `npx -c`.

#### Agree on tests before coding

Append this line to **`.github/copilot-instructions.md`**, keeping the existing rules:

```text
When adding or changing a feature, assess whether tests are needed. Propose relevant tests and ask the user which to add or update, then implement the feature and agreed tests together.
```

#### Explore, propose, then choose

In Chat's agent selector, choose **`playwright-test-planner`**, attach the seed test and send:

```text
Explore the real Playbook presentation with the test MCP.
Propose useful missing tests in specs/presentation.md, such as arrow navigation,
Escape and slide-link reload, each with a concrete expected result.
Ask which tests I want, then wait. Do not generate them yet.
```

Check that browser tools actually ran. Choose your cases, for example: **“Add arrow navigation and Escape; keep the existing sidebar test.”**

#### Generate and run the chosen tests

Select **`playwright-test-generator`**, attach the approved plan and seed, and send:

```text
Generate only my approved cases in tests/e2e/presentation.spec.ts.
Verify selectors and meaningful assertions in the real browser; no duplicates or fixed waits.
Close the browser/preview you started when finished. Do not hide real app defects.
```

Then return to **Agent**: **“Stop the test MCP's preview, run the chosen tests and the normal suite, and explain one assertion and the regression it catches.”** Stop only exercise-owned resources. The optional **healer** must not skip/delete tests or weaken assertions to make them pass.

### 9.2 — Choose tools for web and desktop apps

- **Web, including localhost:** Playwright and its test agents.
- **Native desktop UI:** Computer Use where supported and authorized, or suitable platform-specific tools. It is not a universal test framework.
- **Logic or APIs:** unit/API tests are often simpler.

### 9.3 — Save the exercise, then checkpoint3 and the prepared demo

**Save, commit and push your exercise on `test-creation`; record the branch and commit.** Then run [`./checkpoint3`](/theomonfort/en/handson/intro-2/#checkpoints). It imports a whole snapshot into a separate branch/PR and can replace your tests, agents and instructions. Your work stays on the saved exercise branch: do not blindly merge the snapshot over it.

The **prepared 18-second demo is not your generated tests**. A presenter runs it on the checkpoint branch on a **local graphical desktop**, not a browser-only Codespace. If local dependencies/Chromium are missing, ask Copilot to prepare them first.

```bash
npx --package=node@22.23.4 node ./node_modules/@playwright/test/cli.js test --config=playwright.demo.config.ts
```

Run as written, without `npx -c`. The tour uses one browser window; build/startup are extra time. It stays outside `tests/e2e` and normal CI, uses its own preview and closes it afterward.

Older checkpoint3 copies may lack [`playwright.demo.config.ts`](https://github.com/theomonfort/Github-copilot-workshop/blob/e40b89ae43baa271e5e4f9503b4ed5492c3b7ac5/playwright.demo.config.ts) and [`tests/demo/playbook.demo.ts`](https://github.com/theomonfort/Github-copilot-workshop/blob/e40b89ae43baa271e5e4f9503b4ed5492c3b7ac5/tests/demo/playbook.demo.ts). Add only these two files after review, not the whole snapshot again.

### 9.4 — Check the PR, then continue to security

Return to your saved **`test-creation`** branch with a clean working tree. Ask Copilot:

```text
Reuse existing E2E CI, or add a PR workflow using Node 22, npm ci and matching Chromium.
Run normal headless tests and upload the failure report. Exclude the presenter demo.
```

Commit/push and open the test PR, linked to the existing Issue. Inspect its Actions check and report. If based on an unmerged checkpoint2 PR, review and merge that prerequisite first.

**Continue with [Part 10: Dependabot](/theomonfort/en/handson/test-secure-dependabot/), [Part 11: CodeQL](/theomonfort/en/handson/test-secure-codeql/), then [GHAS](/theomonfort/en/playbook/github-advanced-security/?present=1).** Passing browser tests does not replace security checks.
