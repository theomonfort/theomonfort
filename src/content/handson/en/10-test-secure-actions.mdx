### 11.1 — Create tests for Presentation mode

In Copilot Chat (Agent mode), enter the following:

```
Create a new branch `test-creation` and do your work on that branch.

Create Playwright E2E tests that verify the Presentation site's keyboard navigation.

Assumptions:
- src/content/playbook/ contains at least 2 entries.
- `/playbook/` is the landing page, not presentation mode.
- At desktop size, open a card's presentation link (`/playbook/<slug>/?present=1`) before testing keyboard navigation. Use an existing entry with at least two slides.

Test cases:
1. Pressing `←` / `→` moves to the previous / next slide within the same section (one slide per `##` heading).
2. Clicking a different section in the left sidebar switches to that section's first slide.
3. Pressing `Esc` returns to `/playbook/`.

File layout:
- Place the tests in tests/e2e/presentation.spec.ts.
- Update playwright.config.ts if needed (baseURL, webServer configured to launch `npm run dev`).

Once the tests are written, run `npx playwright test` locally and make sure they all pass.
```

⏱ ~5 minutes

<span id="102--create-an-actions-workflow-that-runs-automatically-on-prs"></span>

### 11.2 — Create an Actions workflow that runs automatically on PRs

Next, enter the following in Copilot Chat:

```
Continue working on the same `test-creation` branch.

Create .github/workflows/test.yml.
Trigger it on PR open / update, and have it perform the following steps:

1. Set up Node.js 22
2. Install dependencies (`npm ci`)
3. Install the Playwright browsers (`npx playwright install --with-deps chromium`)
4. Run `npx playwright test`
5. On test failure, upload the Playwright report as an artifact
```

⏱ ~2 minutes

Commit and push the tests and workflow, then open a PR from `test-creation`. You'll see `test.yml` running in the Actions tab. If you started from an unmerged checkpoint branch, review and merge that checkpoint PR first, then update the test PR as needed. Whenever you change Presentation mode behavior, this workflow will catch regressions early.

<Aside type="positive">

**Key point**: By writing tests and running them continuously through Actions, you get a safety net that catches regressions — even as the Cloud Agent and the upcoming Agentic Workflow start opening PRs automatically.

</Aside>
