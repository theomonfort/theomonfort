[Official Playwright test agents](https://playwright.dev/docs/test-agents) provide a planner and generator using a test MCP server. No custom skill is needed. See also [GitHub Actions](/theomonfort/en/playbook/github-actions/?present=1).

Create `test-creation` from that working branch and use the existing `[playbook:presentation-tests]` Issue from Part 6. Reuse any existing tests rather than duplicating them.

### 9.1 — Create tests for Presentation mode

#### Prepare the official agents safely

**In an updated Codespace, Playwright and Chromium are available.** Elsewhere, use Node 22 and install the project dependency and browser below. If the project dependency is missing in Codespaces, run only the first command. The test MCP is configured in the next step.

```bash
npm install --save-dev --save-exact @playwright/test@1.58.2
npx playwright install chromium
```

**Generate the official agents** in the project root (VS Code 1.105+):

```bash
	npx playwright init-agents --loop=vscode
```

These agent files are **generated automatically**, not written by you:

```text
.github/agents/
  playwright-test-planner.agent.md
  playwright-test-generator.agent.md
  playwright-test-healer.agent.md
```

The initializer also writes `.vscode/mcp.json` and sample seed/setup files. Preserve existing files and workflows. For the [Part 3](/theomonfort/en/handson/plan-mcp/) root setup, ask Copilot to merge the generated `playwright-test` entry into `.mcp.json` and connect the agents to it, keeping GitHub and Context7. Do not replace the root file or start duplicate servers.

If `playwright.config.ts` is missing, ask Copilot to configure the project with `testDir: './tests/e2e'`.

In **Customizations → MCP Servers → Workspace**, start **`playwright-test`** and review the trust prompt. Its command is `npx playwright run-test-mcp-server --headless`, run from this project with Node 22. Check the generated agents under **Customizations → Agents**.

#### Agree on tests before coding

Append this line to **`.github/copilot-instructions.md`**, keeping the existing rules:

```text
When adding or changing a feature, assess whether tests are needed. Propose relevant tests and ask the user which to add or update, then implement the feature and agreed tests together.
```

#### Explore, propose, then choose

In Chat's agent selector, choose **`playwright-test-planner`** and send the following with your running site's URL:

```text
Explore the Playbook presentation at <your running site URL> with the test MCP.
Propose useful missing tests in specs/presentation.md, such as arrow navigation,
Escape and slide-link reload, each with a concrete expected result.
Ask which tests I want, then wait. Do not generate them yet.
```

Check that browser tools actually ran. Choose your cases, for example: **“Add arrow navigation and Escape; keep the existing sidebar test.”**

#### Generate and run the chosen tests

Select **`playwright-test-generator`**, attach the approved plan, and send:

```text
Generate only my approved cases in tests/e2e/presentation.spec.ts.
Verify selectors and meaningful assertions in the real browser; no duplicates or fixed waits.
Close the browser/preview you started when finished. Do not hide real app defects.
```

Then return to **Agent**: **“Stop the test MCP's preview, run the chosen tests and the normal suite, and explain one assertion and the regression it catches.”** Stop only exercise-owned resources. The optional **healer** must not skip/delete tests or weaken assertions to make them pass.

### 9.2 — Choose tools for web and desktop apps

- **Web, including localhost:** Playwright and its test agents.
- **Native desktop UI:** Computer Use where supported and authorized, or suitable platform-specific tools. It is not a universal test framework.
- **Logic or APIs:** unit/API tests are often simpler.

### 9.3 — Save your work and use checkpoint3

**Save, commit and push your exercise on `test-creation`; record the branch and commit.** Then run [`./checkpoint3`](/theomonfort/en/handson/intro-2/#checkpoints). It imports a whole snapshot into a separate branch/PR and can replace your tests, agents and instructions. Your work stays on the saved exercise branch: do not blindly merge the snapshot over it.

### 9.4 — Check the PR, then continue to security

Return to your saved **`test-creation`** branch with a clean working tree. Ask Copilot:

```text
Reuse existing E2E CI, or add a PR workflow using Node 22, npm ci and matching Chromium.
Run the headless tests in tests/e2e and upload the failure report.
```

Commit/push and open the test PR, linked to the existing Issue. Inspect its Actions check and report. If based on an unmerged checkpoint2 PR, review and merge that prerequisite first.
