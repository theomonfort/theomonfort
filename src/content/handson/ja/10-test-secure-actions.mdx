### 9.1 — Presentation モードのテストを作成する

#### 公式エージェントを安全に準備する

[更新済み Dev Container](https://github.com/theomonfort/Github-copilot-workshop/blob/2ee5b723164850e201d770a0522324bb643ff4b3/.devcontainer/devcontainer.json) は **Node.js 22、Playwright 1.58.2 CLI、対応する Chromium** を自動で準備します。古いコピーではコンテナー設定を更新して再ビルドしてください。プロジェクト内の `@playwright/test` 依存関係、設定、エージェントは別途必要です。

不足するものがある場合だけ、Copilot Chat に準備を依頼します。

```text
このプロジェクトで不足する Playwright 1.58.2 の依存関係、Chromium、設定を準備してください。
init-agents --loop=vscode を隔離した場所で実行し、公式 planner/generator を .github/agents に統合してください。
ツールの接続先はルート .mcp.json の headless な playwright-test MCP 1 つにしてください。
既存サーバー、workflow、指示、テストは維持し、利用可能なモデルを使ってください。
testDir は tests/e2e とし、生成テストと /playbook/ を確認する動作する seed をそこに置いてください。
準備、テスト実行、MCP プロセスすべてに Node 22 を使い、ツールの動作確認後に一時物を片付けてください。
```

[Part 3](/theomonfort/handson/plan-mcp/) の Copilot ハーネスと VS Code 1.105 以降を使います。**Customizations → Agents** を確認し、**MCP Servers → Workspace → playwright-test** を信頼確認のうえ起動してください。コンテナー外で別の Node 版を使う場合は、Copilot に準備、テスト、MCP を `npx --package=node@22.23.4 node ./node_modules/@playwright/test/cli.js` 経由にして MCP を再起動するよう依頼します。ターミナルだけの Node 切り替えは MCP に反映されません。`npx -c` は使わないでください。

#### 実装前にテストを相談する

**`.github/copilot-instructions.md`** に、既存の指示を残して次の1行を追加します。

```text
機能の追加や変更時には、テストが必要かを検討する。適切なテストを提案し、どれを追加または更新するかユーザーに確認してから、機能と合意したテストを一緒に実装する。
```

#### 画面を調べ、提案から選ぶ

Chat のエージェント選択で **`playwright-test-planner`** を選び、seed テストを添付して送信します。

```text
テスト MCP で実際の Playbook のプレゼン画面を調べてください。
矢印キー、Escape、スライドリンクの再読み込みなど、不足する有用なテストを
期待結果とともに specs/presentation.md に提案してください。
どれを追加するか私に質問して待ってください。まだ生成しないでください。
```

ブラウザーツールが実際に動いたことを確認し、たとえば **「矢印キーと Escape を追加し、既存のサイドバーテストは残してください」** と選びます。

#### 選んだテストを生成して実行する

**`playwright-test-generator`** を選び、承認した計画と seed を添付して送信します。

```text
私が選んだケースだけを tests/e2e/presentation.spec.ts に生成してください。
実際のブラウザーでセレクターと意味のある assertion を確認し、重複や固定待機は避けてください。
完了したら自分で起動したブラウザーと preview を閉じ、本当のアプリの不具合は隠さず報告してください。
```

通常の **Agent** に戻り、**「テスト MCP の preview を止め、選んだテストと通常のテスト一式を実行してください。assertion を1つ選び、検知する回帰を説明してください」** と依頼します。停止するのは演習で起動したものだけです。任意の **healer** も、テストの skip、削除、assertion の弱体化で成功させてはいけません。

### 9.2 — Web とデスクトップでツールを選ぶ

- **localhost を含む Web：** Playwright とテストエージェント。
- **ネイティブのデスクトップ UI：** 対応と権限がある環境の Computer Use、または専用ツール。万能なテストフレームワークではありません。
- **ロジックや API：** ユニットテストや API テストの方がシンプルな場合があります。

### 9.3 — 演習を保存して checkpoint3 と準備済みデモへ進む

**演習を `test-creation` に保存、コミット、push し、ブランチ名とコミットを控えます。** 次に [`./checkpoint3`](/theomonfort/handson/intro-2/#checkpoints) を実行してください。別ブランチと PR にスナップショット全体を取り込むため、テスト、エージェント、指示が置き換わる場合があります。自分の作業は保存した演習ブランチに残ります。無条件でマージして上書きしないでください。

**準備済みの18秒デモは、今生成したテストとは別物**です。講師が checkpoint ブランチで、ブラウザーだけの Codespace ではなく **GUI のあるローカル環境**で実行します。ローカルの依存関係や Chromium が不足していれば、先に Copilot に準備を依頼してください。

```bash
npx --package=node@22.23.4 node ./node_modules/@playwright/test/cli.js test --config=playwright.demo.config.ts
```

`npx -c` で囲まず、そのまま実行します。1つのウィンドウでツアーを表示し、ビルドと起動は別時間です。`tests/e2e` と通常の CI からは除外され、専用 preview は終了後に閉じます。

古い checkpoint3 に [`playwright.demo.config.ts`](https://github.com/theomonfort/Github-copilot-workshop/blob/e40b89ae43baa271e5e4f9503b4ed5492c3b7ac5/playwright.demo.config.ts) と [`tests/demo/playbook.demo.ts`](https://github.com/theomonfort/Github-copilot-workshop/blob/e40b89ae43baa271e5e4f9503b4ed5492c3b7ac5/tests/demo/playbook.demo.ts) がなければ、確認してこの2ファイルだけを追加し、全体を再取り込みしないでください。

### 9.4 — PR を確認してからセキュリティへ進む

作業ツリーを clean にして保存した **`test-creation`** ブランチへ戻り、Copilot に依頼します。

```text
既存の E2E CI を再利用し、なければ Node 22、npm ci、対応する Chromium を使う PR workflow を追加してください。
通常の headless テストを実行して失敗レポートを保存し、発表用デモは除外してください。
```

コミットして push し、既存 Issue に関連付けたテスト PR を作ります。Actions のチェックとレポートを確認してください。未マージの checkpoint2 PR が前提なら、先にその PR をレビューしてマージします。
