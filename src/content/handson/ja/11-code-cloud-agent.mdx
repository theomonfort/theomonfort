<span id="111--cloud-agent-に-context7-mcp-サーバーを設定する"></span>

### 8.1 — Cloud Agent に Context7 MCP サーバーを設定する

Part 3 で設定した MCP は **VS Code 用** でした。Cloud Agent が MCP を使うには、リポジトリ側に別の設定が必要です（この設定は Cloud Agent と Copilot Code Review が共有します）。

1. github.com で自分のリポジトリを開き、**Settings** タブをクリック
2. サイドバーの **Code & automation** → **Copilot** → **MCP servers** を開く
3. **MCP configuration** 欄に以下の JSON を貼り付け、**Save MCP configuration** をクリック

```json
{
  "mcpServers": {
    "context7": {
      "type": "http",
      "url": "https://mcp.context7.com/mcp",
      "tools": ["resolve-library-id", "get-library-docs"]
    }
  }
}
```

⏱ 約2分

### 8.2 — 既存の Issue に Cloud Agent をアサインする

**最初に必須：[Step 6.6](/theomonfort/handson/code-copilot-chat/#66--改善点を-issue-化する) の `[playbook:presentation-core]`。** `./checkpoint1` が準備した Issue を再利用するか、カタログにない Issue だけ作成します。番号を決めつけず、キーで探してください。`/playbook` は一覧ページのまま残し、各カードから `/playbook/<slug>/?present=1` に入るリンク、矢印キー操作、セクションの目次を追加します。Test & Secure の前に、この PR をレビューして動作確認し、マージしてください。[Step 11](/theomonfort/handson/test-secure-actions/) でこれらの操作をテストします。

1. github.com で自分のリポジトリを開く
2. 上部の **Issues** タブをクリック
3. 一覧からプレゼンモードの Issue を開く
4. 右サイドバーの **Assignees** をクリック
5. リストから **Copilot**（GitHub）、**Claude**（Anthropic）、**Codex**（OpenAI） のいずれかを選んでアサイン

![Cloud Agent アサイン画面](/theomonfort/handson/img/cloud-agent-assignees.png)

アサイン時に以下をカスタマイズできます：

- **追加プロンプト** — Issue の説明に補足指示を追加
- **モデル選択** — Copilot / Claude / Codex から選択
- **ベースブランチ** — 作業の起点となるブランチを指定

<Aside type="positive">

**ポイント**: Cloud Agent がコードを実装して PR を作成します（⏱ 各 Issue につき約15分）。Step 4.1 の Validation Tools の指示だけでは、リポジトリのチェックは有効になりません。Code Review は Step 7 で設定済みですが、CodeQL は Step 10、Playwright / Actions は Step 11 で追加します。この最初のプレゼン PR では後続のチェックを前提にせず、自分で起動して差分を確認してください。

</Aside>

<Aside type="reference">

**おすすめの進め方**:

- **まず `presentation-core` をマージ**し、`presentation-content`、`mermaid-rendering`、`responsive-navigation` に進みます。同じレンダラーを変更する場合があるため、独立した作業だけを並列化します。
- **checkpoint2 の到達点を確認**：テスト前にスライド本文、図、ナビゲーションが動作する状態にします。
- **残りの CLI 作業は Part 13 用に残します。** `playbook-3d` を手動実装するか、checkpoint3 を取り込む場合は既存実装を確認して再利用し、3D のマージ後に `galaxy-audio` を追加します。`daily-repo-status` は Part 14 で扱います。

</Aside>

<span id="113--pr-を確認する"></span>

### 8.3 — PR を確認する

Cloud Agent が作成した PR は **Draft（下書き）** 状態で作成されます。

1. PR を開き、内容を確認
2. **Ready for review** をクリックして Draft を解除
3. Copilot Code Review が自動的に開始されます

<Aside type="negative">

**コンフリクトが発生した場合**: 複数の Cloud Agent が並行して作業すると、同じファイルを変更してコンフリクトが発生することがあります。**Resolve conflicts** → **Fix with Copilot** をクリックすると、Copilot が自動的にコンフリクトを解決してくれます。

</Aside>

![Fix with Copilot でコンフリクト解決](/theomonfort/handson/img/fix-conflicts-copilot.png)

<span id="114--マージ前に-codespace-で動作確認する"></span>

### 8.4 — マージ前に Codespace で動作確認する

マージしてしまう前に、Cloud Agent の PR を Codespace で実際に動かして確認するのが賢い進め方です。`gh` CLI で PR のブランチをチェックアウトしましょう（`<PR番号>` は実際の PR 番号に置き換えてください）。

```bash
gh pr checkout <PR番号> && npm ci && npm run dev
```

Codespaces の転送ポート（ローカルなら表示された URL）から `/playbook` を開き、カードのプレゼンリンクを選びます。`←` / `→`、目次でのセクション切り替え、`Esc` で一覧に戻る操作を確認してください。問題があれば PR にコメントして修正を依頼します。**動作するプレゼン PR をマージしてから Test & Secure に進みます。**
