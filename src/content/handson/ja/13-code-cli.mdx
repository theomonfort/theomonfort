### 13.0 — （Codespace を使っていない場合）Copilot CLI をインストールする

ワークショップ用の Codespace には Copilot CLI が **プリインストール済み** なので、この手順はスキップして構いません。ローカル環境で作業していてまだ入っていない場合だけ、以下のいずれかでインストールします：

```bash
# npm（全 OS 共通 / Node.js 22 以上が必要）
npm install -g @github/copilot

# Homebrew（macOS / Linux）
brew install copilot-cli

# インストールスクリプト（macOS / Linux）
curl -fsSL https://gh.io/copilot-install | bash
```

<Aside type="positive">

**💡 TIP**: 詳しくは [Copilot CLI のインストール（公式ドキュメント）](https://docs.github.com/en/copilot/how-tos/copilot-cli/set-up-copilot-cli/install-copilot-cli) を参照してください。

</Aside>

### 主なコマンド

| コマンド         | 説明                          |
| ------------ | --------------------------- |
| `/help`      | 利用可能なコマンド一覧を表示              |
| `/model`     | AI モデルの選択（Claude / GPT 等）   |
| `Shift+Tab`  | モード切り替え（plan / agent）       |
| `/ide`       | IDE ワークスペースと接続              |
| `/allow-all` | 確認なしでツール実行を許可（Autopilot）    |
| `/fleet`     | 複数エージェントを並列で動かす             |
| `/tasks`     | 実行中の fleet タスクの状態を確認        |
| `/context`   | コンテキストウィンドウのトークン使用量を表示      |
| `/compact`   | 会話履歴を要約してコンテキストを圧縮          |
| `/chronicle` | セッション履歴・利用状況の分析             |
| `/resume`    | 前回のセッションを再開                 |

### 13.1 — Copilot CLI を起動する

まず、前の演習の PR（またはチェックポイント PR）を自分でレビューしてマージします。サイトは準備されたチェックポイントブランチでマージ前に試せます。`/fleet` に進む準備ができたら、ローカルの `main` を更新してください：

```bash
git checkout main
git pull
```

そして VS Code のターミナルで Copilot CLI を起動：

```bash
copilot
```

### 13.2 — モデル選択と Autopilot

CLI 内で以下を実行：

```
/allow-all
```

```
/model
```

最も高性能なモデル（例: Claude Opus 4.6）を選択してください。

### 13.3 — `/fleet` で Issue を並列に実装する

前提の PR がマージ済みの未完了タスクを選びます。checkpoint3 を使う場合は確認済みの 3D を再利用して `galaxy-audio` に進み、使わない場合は先に 3D を実装します。着手可能な作業が 1 件なら CLI の単一セッションで進めます。独立したタスクが複数ある場合は、以下の `/fleet` プロンプトを使います。各実装のラバーダックレビューも依頼しています。

```
/fleet [playbook:キー] で識別される Part 6 の Issue と完了条件を読んでください。
前提の PR がマージ済みの未完了タスクだけを選んでください。
presentation-tests は Part 11、daily-repo-status は Part 14 用に残してください。
checkpoint3 が playbook-3d の完了条件を満たすか確認し、作り直さず再利用してください。
3D がない場合は実装してマージし、その後に galaxy-audio を進めてください。
checkpoint3 を使う場合は、その PR のマージ後に環境音を実装してください。依存する作業を同時に進めないでください。
着手可能な作業が 1 件だけなら、余分なエージェントを起動せずその作業を進めてください。
open Issue やラベルで一括選択せず、範囲が独立した着手可能タスクだけを並列化してください。

各エージェントは以下のフローで作業すること：
1. Issue 番号と一致するブランチ (fix/<number>-<slug>) を切る
2. 修正を実装する
3. npm run dev で動作確認できる状態にする
4. コミットして PR を出す（実際の Issue 番号で `Closes #<number>` を本文に入れる）

すべての PR が作成されたら、各実装に対してラバーダックレビューを行ってください。
```

⏱ 約10〜15分

独立したタスクがある場合は、CLI が別ブランチで実装から PR 作成まで進められます。前提の PR をレビューしてマージしてから、依存する作業を始めてください。完了条件を確認し、スナップショットに含まれる機能を作り直さないようにします。

実行中・実行後の進捗を確認するには：

```
/tasks
```

各 fleet エージェントの状態（実行中 / 完了 / 失敗）と現在のステップが一覧表示されます。

<Aside type="positive">

**ポイント**: 実装させたモデル（Claude）と異なるモデル（Codex）でレビューさせることで、同質性バイアスを避けて盲点を炙り出せます。Copilot CLI には専用の **rubber-duck サブエージェント** が組み込まれており、メインのエージェント（例: Claude）とは別モデル（例: GPT）で批判的にレビューしてくれます。プロンプトに「実装後に別モデルでラバーダックレビューしてください」と書いておくと自動的に呼び出されます。詳細は [About the rubber duck agent](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/rubber-duck) と [About custom agents](https://docs.github.com/en/copilot/concepts/agents/copilot-cli/about-custom-agents) を参照。

</Aside>

### 13.4 — Chronicle で利用状況を分析する

最後に、ワークショップ中の Copilot CLI 利用状況を Chronicle で振り返ります：

```
/experimental
```

```
chronicle
```

<Aside type="positive">

**Chronicle のポイント**: Chronicle は Copilot の利用パターンを分析し、より効果的な使い方のアドバイスを提供します。並列処理した fleet 実行の傾向もここで確認できます。

</Aside>
