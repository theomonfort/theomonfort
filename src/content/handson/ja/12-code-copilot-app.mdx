### 12.1 — リポジトリと仕様書を集める

まず **Codespaces の作業を保存、コミット、push** し、Test & Secure の PR をレビューしてマージします。ハンズオン repo にアクセスできるアカウントで Copilot App を開きます。古いローカルの `main` ではなく、このレビュー済みの状態から続けてください。

1. **Projects の横にある +** から、このサイト用の Project を作成します。
2. 次の3リポジトリを Project に追加します。実装先は自分のハンズオンリポジトリだけです。
3. [Word 仕様書をダウンロード](/theomonfort/handson/copilot-app-project-brief.docx)し、**Library → Add → Add file…** で添付します。

太陽系の参照は、太陽と天文学上の8惑星、紺とアンバーの配色、詳細パネルという、サイトとは異なる構成です。そのままコピーせず、データと操作を **SDLC のカテゴリ、Playbook のルート、レトロテーマ**に合わせます。

### 12.2 — 比較してから計画を承認する

リポジトリ名を置き換え、次の1つのプロンプトを Project に送信します。

```text
Library の Word 仕様書を読み、3つのリポジトリを比較してください。
変更可能なのは <自分のハンズオンrepo> だけで、irl-odyssey の2つは読み取り専用の参照です。
最新の main を基点に、現在の機能とテストを最初に確認してください。
太陽系を SDLC のカテゴリ、Playbook のルート、レトロテーマに合わせることと、
同梱ノートで読み取り専用 Zettelkasten を統合することを、1つの計画とテスト案にまとめてください。
ライセンス、既存機能、コンテンツを維持してください。
仕様書の読み取り専用設定に従い、訪問者の編集、ノート書き込みリクエストやバックエンドを設けないでください。
私の承認を待ってから、自分の repo の専用ブランチに両方の統合と合意したテストを実装してください。
既存機能は重複させず再利用してください。
関連するチェックを実行し、レビューできる差分と結果を示して、自分で起動したブラウザーとサーバーを停止してください。
```

提案された計画とテストを確認し、会話で承認します。

### 12.3 — 統合結果をレビューする

**Overview** と会話で、3D の移動先がサイトのカテゴリとルートに合い、既存機能が引き続き動くことを確認します。グラフ探索、検索、ノート閲覧、リンクが、編集やノート書き込みリクエストなしで使えることも確認してください。

実装先だけの差分、テスト結果、ライセンス表記を確認し、統合 PR を作成してレビュー、マージします。
