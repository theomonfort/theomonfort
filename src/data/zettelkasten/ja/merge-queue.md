---
title: "マージキュー"
---

**マージキュー**（[[PR Rulesets]] 内の `Require merge queue`）は、[[GitHub]] の変更が頻繁な `main` ブランチを、マージ後の意味的な不整合から保護します。承認済みの [[Pull Requests]] を一時的なマージブランチ上で順次またはバッチで検証してから、`main` を fast-forward します。

## 変更の多いリポジトリにマージキューが必要な理由

- [[Required Status Checks]] の strict モードだけでは、`main` へのマージのたびに他のオープン PR の検証結果が無効になり、作成者や [[Auto-Merge]] が `O(N^2)` のリベース競争に巻き込まれます。strict モードなしでは、個別には成功した2つの PR が、組み合わさると `main` を壊す可能性があります。
- **Merge when ready** をクリックすると、承認済みの PR がキューへ渡されます。キューは検証用の `gh-readonly-queue/main/...` ブランチを作成し、`main` + 先行するすべての PR + 対象 PR を組み合わせます。

## ワークフローのトリガーとキュー設定

一時的なキューブランチでチェックを実行するには、CI ワークフローを `merge_group` イベントに対応させる必要があります。

```yaml
on:
  pull_request:
    branches: [main]
  merge_group:
    types: [checks_requested]
```

| ルールセットの設定 | 効果 |
| --- | --- |
| **ビルドの同時実行数とグループサイズ** | キュー内の複数 PR をグループ化し（バッチサイズの `Min` / `Max`）、GitHub Actions の時間を節約。バッチ失敗時は二分探索で原因を絞り、問題の PR だけを除外 |
| **マージ方法** | キュー内の項目にマージコミット、スカッシュ、リベース（[[Merge Methods]]）を一貫して適用 |
| **ステータスチェックのタイムアウト** | 停滞したキュー項目を自動除外し、1件の停止した CI 実行が `main` 全体を止めるのを防止 |
