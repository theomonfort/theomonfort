---
title: "GitHub Flow"
---

**GitHub Flow** は、[[GitHub]] の軽量なブランチモデルです。常にデプロイ可能な単一の `main` ブランチと、[[Pull Requests|プルリクエスト]]で統合する短命な変更ブランチを中心に構成します。

## 4段階のサイクル

1. **`main` からブランチを作成**: 1つの明確な機能や修正に対して短命なブランチを作ります（または [[Stacked Pull Requests|積み重ねたプルリクエスト]]で層状のチェーンを作ります）。
2. **早期に PR を作成**: [[Draft Pull Requests|ドラフトプルリクエスト]]または通常の [[Pull Requests|プルリクエスト]]を早い段階で作り、CI チェックと [[Copilot Code Review]] を起動します。
3. **レビューと検証**: [[PR Rulesets|PR のルールセット]]、[[Required Status Checks|必須ステータスチェック]]、人間のレビューでの指摘をクリアします。
4. **マージとデプロイ**: [[Merge Methods|マージ方法]]または [[Merge Queue|マージキュー]]で統合し、`main` からすぐにデプロイして、`main` を常に出荷可能な状態に保ちます。

## GitHub Flow と複数ブランチによるバージョン付きリリース

| モデル | ブランチ構成 | 適した用途とトレードオフ |
| --- | --- | --- |
| **GitHub Flow** | 単一の長寿命 `main` + 短命な機能ブランチ | Web サービスと継続的デリバリーの標準的な選択。リベース時のずれが最小で、リードタイムが最短 |
| **複数ブランチのリリースフロー（`Git Flow`）** | 長寿命の `main`（`v0.1`、`v1.0` のタグ）+ `develop` と、`feature/*`、`release/*`、`hotfix/*` | 計画的なバージョン付きソフトウェアリリースに限定して使用。二重マージの負担が増える（`release/*` と `hotfix/*` を `main` と `develop` の両方に戻す必要がある） |
