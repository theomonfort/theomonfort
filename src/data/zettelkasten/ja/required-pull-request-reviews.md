---
title: "必須のプルリクエストレビュー"
---

**必須のプルリクエストレビュー**（[[PR Rulesets|PR ルールセット]]内の `Require a pull request before merging`）は、保護ブランチへの直接プッシュをブロックし、[[Pull Requests|プルリクエスト]]で必要な人と AI の承認基準を厳密に指定します。

## サブルールとセキュリティへの影響

| サブ設定 | 適用時の動作 |
| --- | --- |
| **必須承認数（`1-10`）** | [[PR Review States|PR レビューの状態]]の `Approve` 判定の最低数（通常は標準リポジトリで `1`、重要な本番リポジトリで `2+`） |
| **新しいコミットがプッシュされたら古いプルリクエスト承認を取り消す** | レビュー後のコミットでブランチが変わると以前の承認を無効化し、未レビューのコードが以前の承認に便乗することを防ぐ |
| **コードオーナーのレビューを必須にする** | 一致する各ファイルパスについて [[CODEOWNERS]] に指定されたオーナーが承認するまでマージをブロック |
| **レビュー対象となる最新のプッシュへの承認を必須にする** | 最新コミットをプッシュした人が自分のプッシュを承認できなくし、作者が2人の場合の自己承認の抜け穴を防ぐ |
| **マージ前に会話の解決を必須にする** | [[Inline Review Comments & Threads|インラインレビューコメントとスレッド]]のすべてのスレッドを `Resolved` にしなければ、マージまたは [[Auto-Merge|自動マージ]]は実行できない |
| **許可するマージ方法** | ブランチで使用できる [[Merge Methods|マージ方法]]を制限（`Merge commit`、`Squash`、`Rebase`） |

- Organization は、低リスクのリポジトリで問題のない [[Copilot Review Approvals|Copilot レビューの承認]]を承認数にカウントすることを任意で許可しつつ、重要なパスでは人のコードオーナーの承認を必須にできます。
