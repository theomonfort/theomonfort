title: "積み重ねたプルリクエスト"
---

**積み重ねたプルリクエスト**（[[GitHub]] で **2026年7月30日**からパブリックプレビュー）は、依存する [[Pull Requests|プルリクエスト]]を連結し、各ブランチが直下のブランチを対象にする仕組みです（`feat-a -> main`、`feat-b -> feat-a`、`feat-c -> feat-b`）。巨大な差分を、小さく独立してレビューできる層に分けます。

## スタックの仕組みと保証

- **層ごとの保護**：[[PR Rulesets|PR ルールセット]]、[[Required Status Checks|必須ステータスチェック]]、[[Copilot Code Review]] は、[[PR Diff & File Views|PR の差分とファイル表示]]で各層の独立した差分を明確に評価します。
- **自動リベースと対象変更**：下の層をマージすると、その上の PR の対象が自動で `main` に変わり、スタック内の依存ブランチがリベースされます。
- **柔軟で原子的な取り込み**：最下層だけ、下から順に一部、または全層のゲート通過後に**最上位の PR からスタック全体を一括で**マージできます。

## マージ方法ごとの `main` 上のスタック履歴

| 選択した方法（[[Merge Methods|マージ方法]]） | `main` 上に生成されるコミットグラフ |
| --- | --- |
| **Merge commit** | 各層のブランチのコミットを維持し、**スタック全体（`PR #1-3`）を1つのマージコミットで取り込む**（最も完全な履歴） |
| **Squash and merge** | スタック内の各 PR を**PR ごとに1つの squash コミット**（`PR #1`、`PR #2`、`PR #3`）にまとめ、`main` に取り込む（最も簡潔なログ） |
| **Rebase and merge** | `PR #1`、`PR #2`、`PR #3` のすべてのコミットを `main` に順番に再適用し、**マージコミットのない線形履歴**を作る |

- `github.com`、GitHub Mobile、REST / GraphQL / Webhook、および [[gh stack CLI]] を使うターミナルから、スタックを管理し同期できます。
