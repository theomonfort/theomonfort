---
title: "ルールセットのバイパスと評価モード"
---

**ルールセットのバイパスと評価モード**により、管理者は新しい [[PR Rulesets|PR ルールセット]]を実際の [[Pull Requests|プルリクエスト]]で、開発者をブロックせずに試行できます。緊急バイパスを許可された主体がいる場合は、すべての例外を監査できます。

## 適用モード

| 適用状態 | プルリクエストへの実行時の影響 |
| --- | --- |
| **Active** | ルールに従わないプッシュと PR マージを即座にブロック |
| **Evaluate** *（GitHub Enterprise）* | **ブロックせずに**各プッシュと PR でルールセットをシミュレーションし、合否を **Rule Insights**（`Settings -> Rules -> Rule Insights`）に記録。`Active` に切り替える前に不足するチェックや [[CODEOWNERS]] の漏れを修正できる |
| **Disabled** | ルールを評価も適用もせず、ルールセットの定義を保持 |

## バイパスリストのガバナンスと監査可能性

- **既定はバイパスなし**：GitHub ガバナンスの推奨は**空のバイパスリスト**です。管理者に広範なバイパスを許すと、ルールセットが強制的な制御ではなく単なる推奨になってしまいます。
- **緊急対応主体の範囲を限定**：緊急時の例外がどうしても必要な場合（リリースボットの App、インシデント指揮者のロールなど）は、`Always allow` にせず、エントリを **Pull requests only** に限定するか、バイパス時の確認を必須にします。
- **改ざんの痕跡が残る監査証跡**：ルールセットの編集とバイパスによるマージはすべて **Rule Insights** に記録され、[[Commit Signing & Branch Restrictions|コミット署名とブランチ制限]]とともに **Enterprise Audit Log Streaming** を通じて SIEM ストレージにエクスポートされます。
