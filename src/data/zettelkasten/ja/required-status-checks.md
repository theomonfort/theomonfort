---
title: "必須ステータスチェック"
---

**必須ステータスチェック**（[[PR Rulesets|PR ルールセット]]の `Require status checks to pass before merging`）は、指定されたビルド、テスト、lint、セキュリティのジョブが head コミットで `success` を報告するまで、[[Pull Requests|プルリクエスト]]のマージをブロックします。

## なりすまし防止と厳密なブランチ制御

| オプション | 重要な理由 |
| --- | --- |
| **期待するチェックの送信元を固定** | 必須チェック名（`build`、`unit-tests`、[[PR Dependency & Secret Gates|PR の依存関係とシークレットのゲート]]の `dependency-review` など）を特定の **GitHub App**（`GitHub Actions` など）に紐付け、不正なトークンが偽の成功ステータスを投稿することを防ぐ |
| **マージ前にブランチを最新にすることを必須にする** *（厳密モード）* | PR ブランチに最新の `main` コミットを取り込ませ、前提が矛盾する2つの PR によって気づかないうちに `main` が壊れることを防ぐ |
| **作成時はステータスチェックを必須にしない** | 条件に一致する新しいリリースブランチを `main` から作成できるようにし、後続の PR で CI を実行 |

## 厳密なチェックを大規模運用する

- 必須ステータスチェックと [[Auto-Merge|自動マージ]]を組み合わせると、CI 完了後に無人で PR をマージできます。厳密モードによってリベースが頻発する更新量の多いリポジトリでは、[[Merge Queue|マージキュー]]（`merge_group`）と組み合わせるか、[[Agent Merge]] と [[PR Coding Agent Handoff|PR からコーディングエージェントへの引き継ぎ]]で失敗したジョブを自動修復します。
