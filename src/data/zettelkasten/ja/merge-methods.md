---
title: "マージ方法"
---

**マージ方法**は、[[Pull Requests]] と [[Stacked Pull Requests]] のコミットを `main` にどう記録するかを制御します。`Settings -> General -> Pull Requests` で設定し、[[PR Rulesets]] によってブランチ単位で強制できます。

## 3つのマージ戦略の比較

| マージ方法 | `main` への取り込み方 | コミット履歴のトレードオフ |
| --- | --- | --- |
| **マージコミットの作成** | ブランチの全コミットをそのまま残し、マージコミットを通じて `main` に結合（スタック全体を1つのマージコミットにすることも可能） | 中間コミットの監査証跡が最も充実するが、履歴は非線形になる |
| **スカッシュしてマージ** | PR の全コミットを、`main` 上の**1つのコミット**にまとめる | `main` のログが最も簡潔（`1 PR = 1 commit`）。ブランチ上の作業途中の個別コミットは破棄 |
| **リベースしてマージ** | マージコミットなしで各ブランチコミットを `main` 上に順番に適用 | 細かいコミットを残した厳密な線形履歴。元のブランチのコミット SHA は書き換わる |

## リポジトリを整える制御

- **許可する方法**: 管理者はリポジトリ設定で1つ以上の戦略を有効化するか、[[Required Pull Request Reviews]] と `Require linear history`（[[Commit Signing & Branch Restrictions]]）で特定の保護ブランチを制限できます。
- **デフォルトのコミットメッセージ**: スカッシュコミットとマージコミットのタイトル / 本文をカスタマイズします（例: `PR title (#number)` + PR 本文）。
- **ブランチの整理**: `Automatically delete head branches` を有効にすると、[[GitHub Flow]] のマージ済み機能ブランチが直ちに削除されます。[[Auto-Merge]] や [[Merge Queue]] とも組み合わせやすくなります。
