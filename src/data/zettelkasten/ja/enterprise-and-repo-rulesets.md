---
title: "エンタープライズとリポジトリのルールセット"
---

**エンタープライズとリポジトリのルールセット**は、[[GitHub]] で従来のブランチ保護を引き継ぐ、階層的に重ねて適用できる仕組みです。[[Enterprise Governance|エンタープライズガバナンス]]の下、エンタープライズ、組織、リポジトリの各範囲で、**ブランチ、タグ、プッシュ対象パス**へのコード変更が満たすべき条件を強制します。

## 階層的な継承と最も厳しい要件の適用

- **3つの適用範囲（`ENT / ORG / REPO`）**: エンタープライズまたは組織で定義したルールセットは、条件に一致する配下のリポジトリに自動適用され、個別の手動設定は不要です。
- **加算的な適用**: 同じブランチやタグに複数のルールセットが一致すると、**すべてのルールが重なり、最も厳しい要件が優先**されます。配下の組織やリポジトリ管理者はチェックを厳しくできますが、継承したルールを緩めることはできません。
- **主なルール制御**: マージ前の PR 必須化、必要な承認数、新規コミット時の古い承認の取り消し、会話の解決、必須ステータスチェック、コミット署名、強制プッシュの禁止、ブランチ削除の制限などです。

## カスタムプロパティによる動的な対象指定

壊れやすいリポジトリ名リストを管理する代わりに、1つの組織ルールセットと組織が管理する**カスタムプロパティ**（`Organization settings -> Repository -> Custom properties`）を組み合わせます。

1. `business_criticality`（`critical`、`standard`、`experimental`）などの単一選択プロパティを作成します。リポジトリ管理者が適用対象から外せないよう、**`Allow repository actors to set this property = OFF`** にします。
2. 組織のブランチルールセット（`Default branch`）の対象を、フィルター `props.business_criticality:critical` で指定します。
3. リポジトリの分類を `experimental` から `critical` に変えると、PR レビューや強制プッシュ禁止が直ちに適用されます。**変更するのはリポジトリの分類であり、ルールセットではありません**。

## 評価モードとバイパスを認めない運用

- **評価モード**: 新しいルールセットはまず `Evaluate` 状態で導入し、Rule Insights で実際のプッシュ / マージ違反を監査してから `Active` に切り替えます。
- **空のバイパスリスト（ガードレール #15）**: 本番では**バイパスリストを空**に保ちます（[[GitHub Well-Architected Guardrails|GitHub Well-Architected のガードレール]]を参照。「バイパスリストのあるルールセットは、ルールではなくお願いです」）。[[GitHub Enterprise Importer]] の移行切り替えで書き込みを停止している間に限り、一時的な `Repository migrations -> Exempt` バイパスを追加します。
