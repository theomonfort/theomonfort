---
title: "IdP グループとチームの同期"
---

**IdP グループとチームの同期**は、ID プロバイダーのセキュリティグループを [[Enterprise & Org Teams|エンタープライズチームと組織チーム]]に直接対応付けます。リポジトリとロールへのアクセスは常に `IdP -> Teams -> Repositories` を通り、手動管理によるメンバーシップのずれを防ぎます。

## グループの対応付けによるプロビジョニング結果

デフォルトでは、[[SCIM Provisioning|SCIM プロビジョニング]]は [[Enterprise Managed Users]] のユーザーを、組織へのアクセスを持たない**未所属**アカウントとして作成します。**Team settings → Identity Provider Group** で IdP グループをリンクすると、所属先への配置を自動化できます。

| 対応付けの設定 | エンタープライズと組織のメンバーシップの結果 |
| --- | --- |
| **IdP グループのリンクなし** | エンタープライズ内に**未所属**として存在（組織 / チームアクセスなし。エンタープライズから直接 Copilot Business を付与可能） |
| **IdP グループ → エンタープライズチーム** | グループメンバーが複数組織にまたがるエンタープライズチームへ自動同期（`EMU` のみ） |
| **IdP グループ → 組織チーム** | グループメンバーが組織チームへ同期され、**親の組織にも自動参加**（`EMU` と個人アカウントの SAML / SCIM） |

## Microsoft Entra ID グループの制約

[[Entra ID Enterprise App|Entra ID エンタープライズアプリ]]から同期する場合は、次の3つの厳格なプラットフォームルールに従います。

1. **セキュリティグループのみ**: GitHub チームは Entra ID の**セキュリティグループ**にのみリンクできます。Microsoft 365（`M365`）グループは非対応です。
2. **IdP グループの入れ子不可**: Entra ID 内の親子の入れ子グループは、チーム同期時に展開されません。対応付けたセキュリティグループへユーザーを直接割り当てます。
3. **同期済みチームの入れ子不可**: IdP グループにリンクされた GitHub の組織チームは、親または子の GitHub チームを持てません。

[[EMU Type Conversion|EMU タイプの変換]]では、マネキンを再割り当てする前に、移行された空のチームへメンバーを再配置する際にも IdP グループ同期を使います。
